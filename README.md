# Switchboard

A platform that reads any customer conversation or document, works out what it is, runs the analyses
that apply, and sends what matters to the right people in the tools they already use. **Signal Loop**
is the analysis built inside it: product feedback from CSM calls, proved with the customer's own words
and routed to its owner. **Agent Ops** is the sibling product that operates every agent.

Built from scratch in 48 hours by Hunter Borman for Invoca's AI Operations Lead take-home, Option 3:
the feedback loop. Live at `https://repos.hunterborman.com/repo/invoca` (password or signed link).

## What's real and what's simulated

| Area | Status | Notes |
|---|---|---|
| AI pipeline | **Real** | Triage (decision model), extraction (main model), quote checks in code, scoring with a second opinion, themes, routing rules, simulated delivery. Every step is a stored, timed row. |
| Inputs | **Real** | Upload any file (PDF, Word, slides, spreadsheets, transcripts, email, chat exports), paste text, or pick from the sample library. |
| Outputs | **Real** | Each delivery's content, who is tagged and the receipt are generated by the pipeline. |
| Review, evals, budget | **Real** | Human review queue with an audit trail, an eval suite with a promotion gate, a hard $15 viewer budget that switches to replay. |
| Agent Ops for Signal Loop | **Real** | Logs, traces, usage and cost from live runs. |
| MCP server | **Real** | Claude can read the docs, query the data and run the pipeline (see [docs/MCP.md](docs/MCP.md)). |
| Connectors | **Simulated** | Slack, Teams, Jira, Linear, Salesforce, Gmail, Google Drive, Gong, Zoom, Zendesk, HubSpot, Notion. Connecting records a workspace connection; deliveries render as previews; nothing is sent. Routing and tagging behave as they would with real tools. |
| Data | **Simulated** | Fictional accounts, people and 266 calls: real customer conversations can't leave Invoca. |
| Agent Ops' RFP Responder and its history | **Simulated** | A second agent and six weeks of history, to show the platform with more than one agent. |
| Other analyses | **Not built** | Follow-ups, renewal risk, escalations, compliance review, call coaching are listed in the catalog only. |

## How a conversation flows

```
any file ─▶ converted to text in the browser ─▶ POST /api/runs
                                                     │
 ingest ─▶ read ─▶ remove PII ─▶ triage (decision model) ─┐   run in parallel
                                 extract (main model) ────┘
       ─▶ check quotes (code) ─▶ score + second opinion ─┐   overlapped with
                                 theme lookups ──────────┘   the second opinion
       ─▶ route (rules table) ─▶ deliver (simulated tools) ─▶ CSM hears back when it ships
```

One Cloudflare Worker serves the app, the API, the pipeline (fast path, with a durable Workflow as
the fallback), Agent Ops and the MCP server. State lives in D1, similarity in Vectorize, the live-AI
switch in KV. Details: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

A live run of a 13-minute call takes 4 to 7 seconds: triage (~1 s) runs alongside extraction (2 to
4 s), the quote check, routing and delivery are code (under a millisecond), and the second opinion
overlaps the theme lookups. Every step's timing, model, tokens and cost is on the run page and in
Agent Ops.

## Decisions, and what each one beat

- **Code, not n8n, Gumloop or Zapier.** The trust features are code: quotes checked against the
  transcript, typed schemas validated on every model output, deterministic routing, an eval gate,
  budgets and replay, 400+ tests.
- **The model never picks the owner.** Routing is an editable rules table; nothing matched goes to
  triage. A prompt can't be audited the way a table can.
- **No quote, no insight.** Every insight carries a verbatim quote, checked in code; unproven quotes
  are dropped and counted.
- **A person reviews high stakes.** Churn risk, critical bugs and anything under the confidence bar
  wait for review; a second model can send a confident borderline item on or hold a doubtful one.
- **Three model roles, chosen by measurement** on OpenRouter: decision (`z-ai/glm-5.3-flash`), main
  (`deepseek/deepseek-v4.1-flash`), backup and eval judge (`anthropic/claude-haiku-5.5`). See
  [docs/reports/decision-models.md](docs/reports/decision-models.md).
- **One Worker for the proof of concept.** One deploy, one gate, cheap to run. The production design
  moves to Neon, Vercel, Trigger.dev and the Vercel AI SDK with the same boundaries.
- **Option 3 over the RFP responder and the churn watchdog.** It mirrors what Invoca sells, shows
  all four pillars of the brief, and is low risk; the other two can become analyses on the same
  platform later. The full reasoning is in [docs/WALKTHROUGH.md](docs/WALKTHROUGH.md).

## Working in this repo

Requires Node 24+ and a Cloudflare account for remote resources. Copy `.env.example` to `.env`.

```sh
npm ci
npm run dev:vars                       # .dev.vars for wrangler dev, from .env
npm run db:migrate:local && npm run db:seed:local && npm run db:seed:platform:local
npm run dev:worker                     # Worker on :8797
npm run dev                            # app on :5178, proxying the API to the Worker
VITE_FIXTURES=1 npx vite               # the product with in-memory fixtures, no Worker needed

npm run typecheck
npm test                               # unit + Worker integration
npx playwright test                    # product, walkthrough and Agent Ops suites
npm run eval                           # evals on the golden files (spends on the build key)
npm run deploy                         # build, typecheck, migrate, deploy (see the operate skill)
```

## Security

- One gate for everything: a password cookie, a 7-day signed link, or the owner token. The API,
  assets and Markdown docs are all behind it. MCP uses its own workspace-scoped bearer tokens.
- Every viewer gets a private, signed workspace; edits never leak between viewers.
- Personal and health details are redacted before any model sees the text; providers are asked not
  to retain data. Transcript text is wrapped as data; models return a fixed schema and have no tools.
- Spend is capped twice: a reservation ledger in the app and a hard limit on the provider key.
- Secrets live only in `.env` (git-ignored) and Wrangler secrets.

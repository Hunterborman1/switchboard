## Bugs found

- **Fixed: Gong transcripts had wrong timestamps for the first 36 seconds.** The JSON converter read numeric offsets as seconds unless the number was over 36,000, so a Gong sentence at 3,000 ms became 00:50:00 and early turns sorted after later ones. The unit is now decided once per file (Gong monologues are always milliseconds). `src/app/lib/convert/text.ts`; tests in `tests/unit/app/convert.test.ts`.
- **Fixed: JSON transcripts lost their title.** Zoom (`topic`), Gong (`metaData.title`) and similar exports name the meeting, usually with the account, but the converter kept only the turns. The title is now the first line, so the account is detected (Prairie Link above). Same files.
- **Not fixed (Worker, not in this pass's scope): the account is never read from the file name.** `detectAccount` in `src/worker/runs.ts:153` looks at the text only, so "Ridgeway call 2026-10-19.srt", "cedar-ridge-survey-responses.csv" and "coastal-comfort-shared-channel.json" ran with no account, no CSM and no ARR. Suggested change: `detectAccount(input.text, accounts) ?? detectAccount(input.filename.replace(/[-_.]+/g, ' '), accounts)`.
- **Copy fixed: Settings overstated redaction.** It said "health information" is replaced; redaction covers health identifiers (dates of birth, record numbers, patient names), not conditions, so "diabetes medication" reached the models in the .rtf run. Settings now lists what is redacted. Redacting conditions would be a change to `src/pipeline/redact.ts`.
- **Not fixed (small): switching a rule's channel keeps the old destination.** Moving the pricing rule from Slack to Email left "#pricing-feedback" as its destination. Delivery is correct (email goes to the owner's address), but the routing table and review text show a Slack channel for an email rule.
